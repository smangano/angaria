# Reading the tests

The [complete public interface review](../docs/public-interface.md) has its own compile-only target, `angaria_public_api_review`, exercising [proposed application/replay workflows](../examples/api_review.cpp). Those declarations have no definitions, fake runtime, or runnable output; the ordinary tests below still qualify the implemented API.

The [shared-helper audit](../docs/helper-audit.md) maps the focused production and test-only headers. Common Result and process plumbing is shared, while [wire_fixture.h](wire_fixture.h) remains an independent test reference encoder and each scenario retains its expected values. [test_shared_helpers.cpp](test_shared_helpers.cpp) checks the common byte, arithmetic, error, wire-code, Field, and escaping contracts directly.

Milestone 4 follows the [native transport contract](../docs/native-transport.md) and [ordered implementation steps](../docs/milestones/milestone-4.md). Private codecs, history validation, mapped payload storage, and reserved progress underpin public direct send/status, Source delivery, and configured allowed loss. New Sessions use format 2.2/`0xf`; older supported profiles retain their recorded behavior. Step 4.9 combines owner failure and exhaustion scenarios; the [qualification matrix](../docs/native-qualification.md) connects the guarantees to their evidence.

The [Publication/destination tests](test_publication_metadata.cpp) use independently authored bytes to explain immutable headers, ordered snapshots, receipt references, and complete record-size preflight. The [receipt/ring tests](test_delivery_state.cpp) show valid state/presence combinations, epoch-zero and negative times, exact ring windows, wraparound, and full-width sequences. The [framing tests](test_delivery_framing.cpp) connect these local codecs to the journal's existing record geometry and receipt write permissions. These are private representation fixtures, not application send/receive examples; they do not prove acceptance, resolve Registry/history references, or mutate a live Session.

For a guided introduction before reading test fixtures, use the [programmer primer](../docs/primer.md) and [runnable examples](../examples/primer/). The programs use public Angaria APIs, explicit programmatic configuration or TOML loading, and visible Result/Error handling. CTest's `primer_examples` checks the first seven lessons plus lessons 14–16, including process ownership, TOML, direct acceptance, retained publication lookup, receive, owning copies, Source close, and allowed-loss gaps. The eighth lesson runs separately as `registry_walkthrough`, covering concurrent registrars, historical snapshots, owner replacement, and offline Registry inspection.

The [delivery validation tests](test_delivery_validation.cpp) build a real Registry, close its claims, then use private 2.2/core journal fixtures. Read them for complete Queue history after ring wrap, original topology/schema context, old producer/consumer incarnations, acknowledgment times, exact Source pins, released Pending ordering, and unchanged rejection of deliberate corruption. A private immutable-read observer rejects payload-overlapping requests before allocation/I/O, proving metadata inspection skips a large opaque payload while still checking its padding. The [capability tests](test_delivery_compatibility.cpp) leave actual Prepared/Committed journal work pending and prove incompatible attachment rejects before recovery changes any Session or coordination bytes. These fixtures do not provide an application upgrade path or implement send/receive/cleanup.

The ninth lesson runs as `payload_example` and shows schema-driven binary encoding/decoding. Its [codec tests](test_payload.cpp) use independent golden bytes, integer/IEEE boundaries, exact schema versions, malformed inputs, payload bounds, and independent codec lifetime. These payload APIs use the current Registry definitions and remain separate from the legacy Field-template serialization tests.

The tenth lesson runs as `logical_fields_example` using [TOML version 2](../examples/primer/logical-fields.toml). It encodes Boolean, bit-field, enum, fixed-ASCII, and int8 values and preserves a caller buffer on errors. Logical metadata tests check independent wire bytes and corruption, including 65,536 enum entries. Registry/process tests check canonical retries, exact metadata budgets, historical definitions, legacy 2.0 support, logical crash recovery, and incompatible-profile rejection before recovery writes.

The eleventh lesson runs as `message_record_example` and uses [the record tests](test_message_record.cpp) to illustrate header framing, complete publication identity, header-plus-payload caps, owning/borrowed lifetime, and exact Session/schema context. Hand-authored wire fixtures are distinct from the real Registry/history scenario. Successful framing or ID issuance is never presented as publication acceptance or delivery.

The twelfth lesson runs as `capture_example`: an application writes several message types and exact schema versions, exits, and a separate generic CLI renders the capture through retained Registry definitions. Its [script](capture_example.py) checks exact escaped text, unchanged capture bytes, precise malformed/truncated/unknown-record diagnostics, and independent size limits. A [test-only fixture producer](capture_diagnostic_worker.cpp) registers valid control-bearing Field names and writes deliberately invalid Boolean/enum/ASCII values, verifying safe single-line diagnostics while preserving the valid record prefix. Unusual paths and long option names also exercise escaped error context. Native catalog attachment retains normal profile/recovery requirements; this is ordinary file exchange before native Queue transport.

The thirteenth lesson runs as `process_exchange`. Its [script](process_exchange.py) coordinates independent producers, a schema updater, and an owning inspector using explicit readiness handshakes. It terminates the first producer only after a closed capture, checks replacement incarnations/sequences, preserves exact same-sized v1/v2 layouts, and verifies cold inspection after applications exit. The [compatibility matrix](../docs/process-exchange.md#compatibility-and-qualification) connects this workflow to existing native-profile and byte-format checks. A separately labeled private predecessor-profile fixture in [the inspection tests](test_inspection.cpp) qualifies scalar inspection of native format 2.0 without upgrading that profile.

Start with [test_runtime_session.cpp](test_runtime_session.cpp) for Session creation/lifetimes, [test_task_registration.cpp](test_task_registration.cpp) for logical Task registration, and [test_schema_registry.cpp](test_schema_registry.cpp) for Field and versioned schema definitions. Their test comments describe the application scenario, the relevant lifetime or failure rule, and any private setup used to reach that state. Test helpers at the beginning manage temporary files, independent processes, and deliberate corruption; they are test infrastructure rather than application initialization code.

A useful reading order is:

1. `CreationRecordsCreatorEffectiveOptionsAndFrameworkMetadata`: create a Session, use its returned creator Task, and inspect options and Registry metadata.
2. `RegistersOfflineParticipantsBeforeTheyAttach` and `ExactRegistrationIsAnUnchangedLookupIncludingTheCreator`: register logical Tasks through the creator's Registry, inspect attribution, and retry without creating another identity.
3. `ActorRegistryRetainsItsTaskWhileReadOnlyViewsDoNot`: see which views retain a Task claim and when another owner can attach.
4. `PublicationIdsPersistWithinAClaimAndResetOnlyWithANewIncarnation`: issue IDs and observe the identity boundary at Task replacement. This does not send a publication.
5. `ThreadTasksRequireAndRetainTheirParentAndRejectOtherThreads`: register children through the creator's public Registry, then understand parent retention and attaching-thread affinity.
6. `RegistersScalarFieldsWithFullWidthApplicationIdentities` and `RetainsExactVersionsOrderedRepetitionsAndEmptyControlSchemas`: register fixed-width Fields and exact schema versions without confusing IDs, versions, and index slots. `LargeFieldListsPreserveEveryFullWidthReference` demonstrates the count/identity widths independently.
7. [Topology activation](test_topology_activation.cpp) and [endpoint lifetimes](test_endpoint_runtime.cpp): complete drafts, activate Source/Queue/Publishing resources in order, and understand which handles retain ownership. These examples stop at identity handles, before payload delivery.
8. The concurrent registration, coordinated replacement/status, termination, full-log, and malformed-state scenarios: understand recovery and rejection guarantees after learning normal use.

Build instructions are in the [project README](../README.md). Run just the public Session and registration examples with:

```sh
ctest --test-dir build -R '^(RuntimeSessionTest|TaskRegistrationTest|SchemaRegistryTest|TopologyRegistryTest|TopologyActivationTest|EndpointRuntimeTest)\.' --output-on-failure
```

The `native_*_worker.cpp` programs run operations in independent exec processes so tests cannot pass solely because handles share process-local state. The startup/shutdown programs cover resource owners outside ordinary test-body lifetimes. Native crash tests exercise process termination on a running local filesystem; the [native storage contract](../docs/native-storage.md) defines their scope, and the [glossary](../docs/glossary.md) defines the storage and recovery terms.


The fourteenth lesson uses [public direct-send tests](test_publication_api.cpp): issue IDs, send MessageViews, inspect owned/buffered outcomes, repeat/conflict, preserve headers, validate exact schemas, wrap a ring with an offline consumer, and query earlier incarnations. These are operational public calls. Private history reads only verify their storage guarantees. Legacy-profile edits are clearly labeled offline fixtures, not upgrade APIs.

The [publication fault tests](test_publication_runtime.cpp) exercise the same engine through a private journal-injection seam: precommit rollback, committed repair, OutcomeUnknown, every Queue/ring redo word, full-log repeats, and exhausted operation generation. The [native crash suite](test_publication_recovery.cpp) kills a separately executed producer at commit checkpoints and resolves its ID through public status on a replacement Task. [Message tests](test_message.cpp) separately demonstrate full-header copying, exact retained decoding context, and the unbound raw-view restriction; public incoming bound views are exercised by the Source tests below.

The fifteenth primer lesson and [public Source tests](test_source_runtime.cpp) now receive through that native path, inspect full headers, copy messages before finishing their borrow, release/redeliver, acknowledge, close/reopen, and move endpoints. They distinguish a stable borrowed mapping from an owning Message, including after runtime handles close. Thread/fork ownership, ring overwrite, membership growth, empty/opaque payloads, exact tokens, and an exactly full log have explicit scenarios. The shared [Source fixture](source_fixture.h) configures real public Registry entities; the [log-budget helper](native_log_budget.h) is clearly labeled private qualification setup.

[Lifecycle tests](test_source_lifecycle.cpp) cover unreturned committed issuance and stale deferred markers that must never clear a newer pin. [Deadline tests](test_source_deadlines.cpp) deliberately delay private metadata reads to check expiration after recovery, separating a fresh issuance from an existing pin. The [consumer-process suite](test_source_recovery.cpp) kills a separately executed public consumer after receive, acknowledgment, release, or close, then checks replacement and delivery order. Existing private journal crash-cut tests continue qualifying the underlying reserved progress transactions. These are process-recovery tests, not power-loss durability tests.

The [sixteenth primer lesson](../examples/primer/16_allowed_loss.cpp) and [allowed-loss API tests](test_allowed_loss.cpp) configure stale-data loss, inspect inclusive gaps, protect an in-flight message across ring overwrite, and preserve the recovery default. They cover release/close/replacement, Source counters and deadlines, exact full-log progress, and precommit/uncertain outcomes. [Configuration tests](test_loss_configuration.cpp) compare TOML and public descriptors and reject allowed loss on an existing core-only Session. [History validation tests](test_loss_validation.cpp) qualify Lost presence, terminal ordering, actual acknowledgment context, policy, and capability using clearly labeled private corruption.

[Compact loss redo tests](test_loss_redo.cpp) reject malformed/unsupported intent before writes. The [native loss recovery suite](test_loss_recovery.cpp) kills an independently executed public consumer at journal phases and every streamed receipt/Queue word, then attaches a replacement through public APIs. Repeatedly interrupted replay must reinstall the captured timestamp, preserve history, and never repeat a committed-but-unreturned gap. These private checkpoints do not form part of the application API.

Step 4.9 combines those guarantees in [transport recovery tests](test_transport_recovery.cpp). Independent producer and consumer workers overlap: the consumer keeps a pin while the producer wraps the ring and dies during publication. Repeated recovery and later consumer replacement qualify both delivery policies together with acceptance lookup and stale tokens. Other cases make a producer operation recover a committed acknowledgment, and combine mixed terminal/pending history with repeated cleanup at a full log. The [shared process owner](native_process.h) handles worker lifetimes; scenario handshakes and private checkpoints stay in the [worker](native_transport_worker.cpp).

[Transport exhaustion tests](test_transport_exhaustion.cpp) use clearly labeled private boundary edits, then reach the final publication ID, Source issuance, or operation generation through public calls. They check unchanged rejection, full-log repeats/status, protected pins, and the different reset rules of each counter. [Native I/O tests](test_transport_io.cpp) hold a real consumer borrow while a separate [producer worker](native_transport_io_worker.cpp) lowers only its own OS file-size limit, observes an actual failed file extension, restores its limit/signal handling, and retries the original identity. The [qualification matrix](../docs/native-qualification.md) records what each kind of evidence establishes and its limits.
